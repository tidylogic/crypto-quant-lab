# PPP 계좌 낙폭 관리

## 가설

기존 C/E/G의 개별 가격 손실보다 전액 10배 계좌 노출과 연속 손실이 큰 낙폭을
만들 수 있다. 동일한 신호·청산에 노출 크기와 확정 손실 후 대기를 적용하면,
수익을 일부 포기하면서 계좌 낙폭을 낮출 수 있다는 가설을 검증한다. 사용자는
제시한 여섯 관리 방식과 통합 HTML 보고서 설계를 승인했다.

## 그대로 유지하는 조건

BTC/ETH/ZEC, 해당 차트 주기의 SMA20/50/100/200 엄격한 정·역배열과 기존 C/E/G
진입 필터를 유지한다. 기존 청산 중 C는 R0/R4, E는 R0, G는 R0/R2를 비교한다.
R0는 반대 크로스만, R4는 추가 1.5 ATR 종가 손절, R2는 추가 SMA50 반대편 종가
청산이다. 봉 마감 확인 후 다음 봉 시가 체결한다. 리스크 없는 경우도 포함한다.

각 조합은 독립적인 $1,000 계좌이며 계약 레버리지는 10배다. 편도 수수료 0.02%를
진입·청산의 실제 명목가치에 적용하고 출금·입금 없이 재투자한다. 기존 자료와
같은 KST 2026-04-14 00:00–2026-10-14 00:00 직전으로 고정한다. Binance는 모든
1·3·5·15분 6개월, MEXC는 5·15분 6개월 및 1·3분 짧은 기간으로 구분한다.

## 크기와 손실 대응

| 코드 | 현금 배정 규칙 |
|---|---|
| Q0 | 전액 100% |
| Q1 | 50% |
| Q2 | 25% |
| Q3 | 신호 ATR14 기준 예상 계좌 손실 1%, 현금 배정 상한 50% |
| Q4 | Q3 + 확정된 자기 거래 2연패 후 6봉 신호 대기 |
| Q5 | Q3 + 확정 폐쇄 잔고 고점 대비 10% 낙폭이면 절반, 20%면 4분의 1 |
| Q6 | Q3·Q4·Q5 모두 적용 |

계좌 잔고 E, 배정 비율 w, 계약 레버리지 L=10, 편도 수수료 f일 때 주문 명목가치
`N = E*w*L/(1+L*f)`다. 배정 현금은 초기 증거금과 진입 수수료를 모두 부담한다.
나머지 현금은 주문에 노출되지 않는다. 10배 계약 설정과 계좌 전체 노출은 다르다.

진입 신호 종가 P, 신호 ATR A, 방향 d(롱 +1/숏 −1)에서 예상 ATR 손실 비율은
`r = 1.5*A/P`, 예상 수수료 포함 단위 손실은 `r + f*(2-d*r)`다. Q3의 비율은
`min(0.5, 0.01*(1+L*f)/(L*(r+f*(2-d*r))))`다. Q5/Q6는 이 비율을 추가 축소한다.
실제 진입 시가의 갭, 실제 R0/R2 청산 수준에 따라 달라지므로 1% 확정 손실 한도가
아니다. 추가 낙폭 축소도 손실을 강제 청산하지 않으므로 20% 최대 낙폭 보장이 아니다.

## 시간 인과성과 자기 계좌 상태

ATR·가격은 해당 진입 신호 봉의 확정 값만 사용한다. 손실 카운터와 낙폭은
`실제 청산 시각 <= 새 진입 신호 봉의 시작 시각`인 **자기 계좌가 받아들인 거래**만
갱신한다. 같은 시가 반전은 이전 신호 봉에서 주문했으므로 그 시가의 결과를 미리
알고 취소하지 않는다. 현금 재투자 규모는 실제 체결 후 이용 가능한 자기 잔고를
사용한다. 대기 중 건너뛴 거래의 가상 손익은 다음 크기·연패 판단에 쓰지 않는다.

2연패를 확인하면 실제 두 번째 청산 시각부터 6봉 구간의 새 신호를 막고 카운터를
초기화한다. 중간에 이익 결과가 확정돼도 이미 정한 대기 종료 시각은 앞당기지 않는다.
Q5/Q6의 고점은 확정 폐쇄 잔고 고점이며, 잔고 회복 시 크기가 다시 증가할 수 있다.
보유 중 평가자산 고점으로 크기를 바꾸는 실시간 방식은 이번 범위에 포함하지 않는다.

## 검증한 거래 기회 재생 범위

교차는 수학적으로 항상 번갈아 발생하지 않는다. 예를 들어 기준선을 정확히
접촉하고 같은 방향으로 다시 움직이면 up/up이 가능하다. 이 경우 단순 기존
거래 기록으로 신규 진입을 재생하면 건너뛴 포지션 안의 새 진입 기회를 놓칠 수 있다.

따라서 실행 전에 **24개 데이터셋의 전체 필터 없는 C 교차 배열**에서 방향이
번갈아 발생하는지 확인한다. 실제 사용 데이터는 연속 동일 방향 이벤트가 0개다.
다른 데이터에서 이 조건이 깨지면 실행을 거부하고 사건별 진입 시뮬레이션을
사용해야 한다. 이 데이터 범위에서만 기존 저널이 모든 진입 기회를 보존한다.
관리 없는 Q0는 이전 복리 계산의 120개 조합과 정확히 같음을 검사한다.

## 성과 평가

종료 평가자산은 미청산 포지션의 진입 수수료·마지막 종가 평가손익을 포함한다.
폐쇄 거래 낙폭과 보유 중 OHLC 고·저점 낙폭 상한을 구분한다. 후자는 봉 안에서
유리한 극값 이후 불리한 극값이 나온 것으로 보는 보수적 순서다. 실제 청산 시가의
갭은 포함하며 그 뒤 청산 봉의 고·저점은 제외한다. 실제 공정가격 계좌 낙폭은 아니다.

단위 손익비는 받아들인 가격 거래의 평균 순수익률/평균 순손실률 절댓값이다.
계좌 손익비는 각 거래 시작 잔고 대비 순수익률로 같은 계산을 한다. 크기 조절로
둘은 달라질 수 있다. 승률은 실제 받아들인 폐쇄 거래에 대해 계산한다. 단순 크기
축소는 가격 거래 승률을 바꾸지 않으며, 대기만 거래 표본을 바꾼다.

앞 4개월과 뒤 2개월은 계좌·카운터·고점을 초기화해 독립적으로 실행한다.
시작 전 포지션을 이어받지 않고, 끝에 열린 포지션은 평가만 한다. 이미 전체
기간을 보며 규칙을 결정했으므로 뒤 2개월은 미관측 검증이 아니다. 작은 고정 메뉴를
비교하며 최종 잔고만 최대화하는 파라미터 격자 탐색은 하지 않는다.

펀딩·슬리피지·최소 주문 단위·계약 수량 한도·강제청산은 제외한다. 가격 평가자산
0 이하 접촉은 별도 기록한다. 강제청산은 공정가격과 유지증거금 등에 의존하므로
일반 거래가격 OHLC만으로 실제 청산 여부를 확정하지 않는다.

## 재현

```bash
python scripts/ppp_drawdown_backtest.py
python scripts/ppp_drawdown_report.py --plots
python scripts/ppp_research_html.py
python -m unittest discover -s tests -v
```

런타임 출력은 git에서 제외된 `user_data/backtest_results/ppp-drawdown-2026-10-14/`다.
`results.json`, `summary.csv`, `managed-trades.csv`, 그래프, 한국어 상세 보고서 및
그림·Pine 소스를 포함한 단일 `ppp-research-report.html`을 제공한다. 원시 캔들 및
대용량 거래 CSV는 HTML에 반복해서 넣지 않고 별도 보조 파일로 보존한다.
